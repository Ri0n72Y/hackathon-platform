# LabourChain · 绳网布局提取与页面方案（D2 候选）

> **日期：2026-11-12｜Product Interface Designer**
>
> 已确认的 D1 方向见 [LabourChain 视觉风格与配色规范](./LabourChain-Visual-Style-Guide.md)：绳网式暗色信息界面，融合 Discord 偏蓝蓝紫主色。
>
> 本文研究**布局**而非仅配色。区分原作截图的可见特征、社区同人实现代码、LabourChain 的 D2 布局建议。**提案尚未通过真实屏幕验收，不改变已确认的项目主页、Issue 路由及数据语义，不要求直接使用其他项目组件。**

## 1. 参考资料与可信边界

### A. 游戏界面截图：可直接观察的视觉现象

1. [電撃オンライン｜《绝区零》Inter-Knot 推送界面实机截图](https://dengekionline.com/article/images/202407/9686/72894)：顶部一行胶囊标签，中间选中项为明黄；正文区为三列不等高的图片贴文卡片；卡片底部聚合作者、标题与摘要，图片与正文通过深色区域分层。
2. [游戏日报｜中文绳网推送截图](https://news.yxrb.net/mobile/index.php?a=show&c=index&catid=6&id=3141&m=mobile)：同样的三列卡片、顶部活动胶囊，以及图片/头像/用户信息/正文预览的卡片纵向顺序。
3. [Pocket Gamer｜游戏内 Inter-Knot 社交帖子画面](https://www.pocketgamer.com/zenless-zone-zero/review/)：图片优先、暗色帖子卡片、浏览量及作者识别信息与封面结合。

**证据边界**：截图只能证明所示宽高下的视觉层级和相对排列；不能据此推定官方 CSS 网格、具体 Breakpoints、键盘行为或原生网页布局。游戏内绳网是游戏菜单，其内容和交互时长与劳动项目中的长篇 README/Issue 不同。截图存在版本/内容差异，不假设所有版本界面完全一致。

5. [ChrisChan13/zenless-ui · `packages/card/card.scss`](https://github.com/ChrisChan13/zenless-ui/blob/main/packages/card/card.scss)：`20px 20px 0 20px` 的非对称卡片外形、图片与作者条/文字区域叠合的边界。
6. [ChrisChan13/zenless-ui · `packages/tabs/tabs.scss`](https://github.com/ChrisChan13/zenless-ui/blob/main/packages/tabs/tabs.scss)：圆角胶囊导航、分割层次和选中态的斜切视觉；该实现中 Tab 为 `40px` 高、`150px` 最小宽度，属于第三方实现尺寸。
7. [KawaYiLab/InterKnot-Web](https://github.com/KawaYiLab/InterKnot-Web)：公开元信息标识其为以《绝区零》绳网为原型的 Nuxt/Vue 论坛前端，项目 README 指向原作者和 Zenless UI。**本轮未能通过连接取得该项目的实际组件源码，故不据此编造栅格与组件尺寸**。

## 2. 从来源提取的布局规律

| 原作截图与同人实现观察 | 可提取的布局规律 | 对 LabourChain 的设计含义 |
| --- | --- | --- |
| 顶部暗色带内有紧密的胶囊分区，活动项显著突出 | 导航与内容之间存在**清晰的层级边界**；一个活动状态优先突出 | 顶层身份和导航形成稳定窄条；仅真实选中项使用蓝紫填充/亮黄少量标记 |
| 三列、不等高封面贴文，卡片有紧密间距 | **浏览模式：卡片优先、快速扫描**，每张卡片内部信息顺序相对固定 | 适合未来平台项目发现或卡片探索视图；不直接改变当前 Repo Feed 已确认的文章式单列阅读 |
| 封面、作者身份条、标题、摘要相继出现 | **卡片内视觉层级**：标识 → 内容 → 次级说明，可用区域背景/边线分层 | Repo Issue 卡片用元信息、标题、正文/媒体块、操作区四段式表现；缺少封面时不伪造 |
| 标题相对醒目，摘要与计数为低对比文字 | **阅读密度分级**：标题 > 主内容 > 次级元信息 | Issue 标题保持比 Markdown 内部 H1 更强的视觉主次，元信息小字号 |
| 第三方详情大屏 4:5 分栏，小屏纵向堆叠 | **上下文与正文按空间条件切换排列** | LabourChain 独立 Issue 可以按“内容优先”重排侧边属性/媒体；保留既定 URL、讨论/劳动 Tab |
| 非对称卡片角、胶囊、浅层纹理 | **信息块具有识别性轮廓**，不依赖插图也可建立风格 | 卡片轻微非对称角、短边线与低对比纹理可作为局部视觉特征，避免每处重度装饰 |

**不直接继承的原型元素**：整页瀑布流取代长文 Feed、点击文章打开对话层、固定等级/经验进度、非网页式全屏操作提示、把所有内容都强制压成封面卡片。这些与现行 LabourChain 的信息架构或数据来源不匹配。

## 3. LabourChain 布局基础规则（D2 建议，非官方精确参数）

### 3.1 页面栅格与间距

| 布局 Token（提案） | 建议值 | 设计用途 |
| --- | --- | --- |
| `page-max` | 1120px | 全站主要内容框架的设计上限 |
| `read-max` | 760px | Issue/README 文章可读行宽上限；媒体可在卡片宽度内自适应 |
| `form-max` | 640px | 现有成员登记单列表单设计基线 |
| `grid-columns` | 12（桌面概念栅格） | 只用于设计对齐，不限定 React/CSS 实现 |
| `page-inset-desktop` | 32px | 宽屏左右安全留白 |
| `page-inset-tablet` | 24px | 中屏左右安全留白 |
| `page-inset-mobile` | 16px | 320/375px 视口左右安全留白 |
| `section-gap` | 28–36px | Hero → Team → Feed 的分段呼吸 |
| `card-gap` | 16px | 单列文章卡片的纵向间距 |
| `card-padding` | 20–24px 宽屏 / 16px 窄屏 | 文字卡片内部间距 |
| `control-height` | 不低于 44px 为主要操作的设计目标 | 可见的主要触达目标 |
| `card-corner` | 12–16px；可在一处角采用小切角/非对称处理 | 有辨识度但不妨碍内容与焦点 |

`page-max` 是新布局候选值，与目前 repo-home CSS 的 960px、Issue Detail 的 960px 不同；**不能在未进行真实页面对比前当作最终审批尺寸**。不要求照搬第三方 `250px` 网格列宽。

### 3.2 响应式折叠建议

- **小屏 320–599px**：单列布局、16px 内边距；顶部导航容器允许自身横向滚动，页面整体不得横向溢出；Hero 操作自然换行；Team 保留单行头像横向滚动；文章/媒体卡片全宽；成员资料/个人链接表单单列。
- **中屏 600–899px**：项目主页仍是单列阅读；Hero 与主要操作可按空间重排；成员资料页面允许在内容可读时过渡到双列，不能强制两列导致内容拥挤。
- **宽屏 900px 及以上**：全站框架上限约 1120px；长篇正文阅读宽度约 760px；Hero 的项目身份与链接操作可相邻分区，但整体视觉顺序仍是项目介绍 → Team → Repo Feed；不额外生成内容侧栏。
- **200% 浏览器缩放**：依实际可用 CSS 视口落入较窄布局；侧栏和表单应重新排列，不能锁定固定画布尺寸或横向挤压正文。

**特别注意**：Flutter 同人项目的 `600/800` 是其自有实现分界，以上 `600/900` 是 LabourChain 的网页 D2 选择，不声称源自《绝区零》官方。

## 4. 项目主页方案：绳网式阅读社区（当前 MVP）

### 4.1 宽屏（结构线框，非最终视觉稿）

```text
┌──────────────────────────── 全站内容宽度 ≤ 1120 ────────────────────────────┐
│ 顶部身份条   LabourChain / owner · repo                 真实站点导航 / 登录  │
├─────────────────────────────────────────────────────────────────────────────┤
│ HERO     项目名称                                                              │
│          Description 或 README 文本摘要                                        │
│          完整 README · GitHub 仓库入口          展示分支 / 对应状态              │
├─────────────────────────────────────────────────────────────────────────────┤
│ TEAM     标题           ○ ○ ○ ○ ○ →（横向滚动）       查看全部成员              │
├─────────────────────────────────────────────────────────────────────────────┤
│ REPO FEED  标题 / 已有筛选和刷新入口                                           │
│ ┌───────────────────────── 文章卡片 / 阅读宽度 ≤ 760 ───────────────────────┐ │
│ │ #编号 · Open/Closed · 作者 · 更新时间     （细标签 / 次级元信息）           │ │
│ │ Issue 标题（主要层级）                                                      │ │
│ │ Markdown 正文前段：段落 / 图片 / 视频外链 / 代码块                           │ │
│ │ 展开完整正文 / 收起正文                                                      │ │
│ │ ──────────────────────────────────────────────────────────────────────── │ │
│ │ 进入讨论                                    GitHub 原文                    │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│ 下一条卡片…  [更多/加载状态]                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

**视觉借鉴路径**：参考绳网顶部暗色分区、活动标签、卡片元信息与正文的多级层次；把封面优先的三列扫描模式**调整成单列文章阅读**。这是对既有产品决策的保留：主页仍显示 GitHub Issue **第一楼完整 Markdown 内容的可展开前段**，不含 Board、伪造封面、虚构等级/热度、独立瀑布流。

### 4.2 窄屏（结构线框）

```text
┌───────────────────── ≤ 375px ─────────────────────┐
│ LabourChain | 项目身份 / 导航（局部滚动/换行）     │
│ 项目名                                              │
│ 简介                                                │
│ README / GitHub 链接                                │
│ 展示分支 / 操作                                      │
│ ─────────────────────────────────────────────────  │
│ Team  ○ ○ ○ ○ →      查看全部成员                     │
│ ─────────────────────────────────────────────────  │
│ Repo 动态 + 当前实际状态                             │
│ ┌───────────────────────────────────────────────┐ │
│ │ 状态 / 编号 / 作者 / 时间                       │ │
│ │ Issue 标题                                     │ │
│ │ 正文 / 媒体块（保持原文顺序）                     │ │
│ │ 展开 / 收起                                    │ │
│ │ 站内详情     GitHub 原文                       │ │
│ └───────────────────────────────────────────────┘ │
│ 按需继续加载                                        │
└─────────────────────────────────────────────────────┘
```

### 4.3 贴文卡片的次级样式

- **轮廓**：`surface` 暗面板，`stroke` 边线，单侧可用斜切/非对称圆角，限定在卡片或导航的少数结构处。
- **元信息**：真实 Open/Closed 状态、Issue 编号、作者、更新时间在卡片顶行；状态胶囊有明确文字，不能只用蓝/黄区分。
- **主体**：Issue 标题高于正文 Markdown H1；段落保持阅读行高，Markdown 媒体在原文位置呈媒体块；没有封面时保持纯文本卡片，不占空白封面位。
- **操作**：站内详情和 GitHub 原文分开；长正文的展开收起遵循原有内容截断与焦点规则。
- **滚动**：只使用当前已有 Feed 连续下拉/加载方式；顶部、卡片与媒体不得嵌套大面积独立滚动区域。代码块和表格可在其自身范围横向滚动。
- **蓝紫与黄**：使用已确认 [视觉规范](./LabourChain-Visual-Style-Guide.md) 的蓝紫主交互色；黄色可用于少量真实焦点信息/醒目的分区标识，不把所有 Open Issue 都高亮为黄色。

## 5. 其他既有页面的布局映射

| 页面 | 绳网可借鉴部分 | LabourChain 当前建议 |
| --- | --- | --- |
| `/{owner}/{repo}/members` | 头像 + 名称 + 身份数据紧凑成组 | 继续采用桌面两列资料卡/窄屏一列；完整简介与链接可读，不改成员 JSON 排序 |
| `/{owner}/{repo}/members/register` | 暗色底、清晰输入面板、胶囊式主要操作 | 继续单列约 640px 表单；姓名与 URL 错误就近反馈，不虚构游戏式等级/奖励 |
| `/{owner}/{repo}/issues/{number}` | 详情内容与上下文的视觉分区；第三方实现可响应式改成纵向阅读 | 保留**独立 URL**、社区讨论优先、讨论/劳动双 Tab，侧边任务属性按既有规则默认隐藏、按需展开；若未来有真实媒体，可在正文流内呈现 |
| 后置 `/{owner}/{repo}/kanban` | 标签、状态胶囊、紧凑卡片与动态分区 | 仅继承视觉 Token；不改变后置排期、看板路由和 Label/DnD 数据规则 |
| 平台入口 `/` | 绳网三列封面扫描在视觉上适合发现 | **仅作未来项目发现页的可选布局探索**；当前 MVP 未确认入口有封面或三列社区卡片 |

**明确的冲突处理**：同人实现 `DiscussionPage` 通过模态弹层呈现两栏详情，但 LabourChain 已确认详情页使用可分享/可刷新 URL；因此保留“宽屏内容分区＋窄屏重排”规律，不采纳对话式导航。三列瀑布流的阅读预览与 LabourChain 第一楼长 Markdown 阅读目标不同，暂不纳入当前项目主页。

## 6. 源码差距与验收边界（静态视觉审查）

| 当前代码区域 | 当前观测到的布局 | 与新布局建议的关系 |
| --- | --- | --- |
| `plugins/repo-home/src/RepoHome.module.css` | 页面 `max-width: 960px`，Hero → Team → Feed；卡片单列，Team 横向一行，移动断点 680px | **信息结构符合**；新增的 1120px 画布候选、模块化轮廓及导航节奏尚未核对实屏 |
| `plugins/repo-home/src/SafeMarkdown.module.css` | 正文 15px / 1.7 行高，图片/视频块与代码块有单独样式 | 阅读顺序基础可沿用；暗色媒体层级、长链接和高缩放仍需用户实屏检查 |
| `plugins/issue-detail/src/IssueDetailView.module.css` | 详情阅读宽度 960px，部分摘要双列，600/380px 断点 | 内容分区具备基础，需与新暗色主视觉和 760px 阅读栏候选对齐；不自行更改左右侧栏行为 |
| `apps/playground/src/style.css` | 较旧的浅色全局入口布局与实验用页面 | 只作为静态现状；真实生产页面是否呈现同一效果应由用户验证 |

**验收方式**：

- **D1 已确认**：暗色绳网社区风格与蓝紫主交互色。
- **D2 本研究交付**：截图/源码布局提取、当前页面线框、布局 Token **候选**、与现有信息架构的冲突处理。
- **D3 未新增业务行为**：Hover/Focus/Tap、Markdown 展开、Issue 导航、成员登记和权限反馈沿用现行 UX Baseline。
- **D4 未测**：页面截图、320/375/768px、200% 缩放、键盘与触屏验收由用户在真实浏览器执行。Designer 仅可在具备本地环境时做辅助设计复审。
- 该研究 PR **不包含业务代码、不添加依赖、不更改 GitHub 数据或权限**。用户确认具体版式后由 Lead 协调独立视觉实施任务。
