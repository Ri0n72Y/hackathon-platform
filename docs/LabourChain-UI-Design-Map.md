## 0. 如何读这份地图

**状态类型（设计本身）**

- **✅ 决策已确认**：页面定位、重要语义或主要交互规则已经商定并记录；不需在后续轮次反复征求象征性批准。
- **🟡 部分完成**：有明确方向或低保真示意，但布局细节、真实行为或异常场景尚未收敛。
- **⬜ 待设计**：当前没有足够具体的页面/交互设计，不能仅凭候选功能判断为完成。
- **⏸ 暂缓 / 其他 Issue**：不属于当下 #2 的 Board 与 Issue UI 主要设计交付。

**交付成熟度（与上方状态不同）**

1. **D1 · 方向/语义**：用户目标、对象、信息层级和不可违反的规则明确。
2. **D2 · 界面结构**：有对应页面的布局/线框、导航与控件位置。
3. **D3 · 行为契约**：关键操作的前置条件、状态变化、可见反馈、失败与恢复均可验证。
4. **D4 · 交互验证**：真实可操作原型经过至少一次完整场景认知走查；键盘、窄屏、空态和错误路径得到检查。

**目前 D4 尚未完成。** 此前聊天中的可切换示意是**探索性低保真演示**，不等于实现路由、GitHub 写入或通过真实测试。

### 0.1 新增视觉决策与证据范围（2026-11-12）

- ✅ **视觉方向 D1 已确认**：采用《绝区零》绳网（Inter-Knot）的模块化卡片、胶囊标签与少量明黄信号语言，融合 Discord **偏蓝的蓝紫主色**；**既有五页暗色稿为 Dark Mode，用户新增要求完整 Light Mode**，双主题共享布局。

- ✅ **五页面 D2 主布局已确认**：产品方确认此前对话演示的 Repo Home、成员列表、成员登记、Issue 详情和独立 Topic Page 方案；详细桌面/手机结构及语义边界见 [五页面布局设计](./LabourChain-Five-Page-Layout-Design.md)。**具体像素值仍是 D2 建议，用户 D4 未验收**。
- 🟡 **绳网布局证据**：游戏截图显示顶部胶囊分区及三列封面贴文，同人源码有瀑布流与详情响应式分区；LabourChain 采用其卡片信息层次，**Repo Feed 保留单列长文，TopicPage 使用封面项目卡**。证据与候选尺寸见 [布局研究](./LabourChain-InterKnot-Layout-Study.md)。

**与旧状态的关系：** 原设计主要确认信息层级和交互；现已确定一致的绳网式五页结构 + Dark/Light 两套外观。旧的浅色源码不能直接视为新的 Light Mode 合格实现，也不能作为双主题验收完成的证据。

## 1. 页面与导航地图

```mermaid
flowchart TB
    ROOT["平台入口 / （本轮不细化）"]
    HOME["仓库首页 /{owner}/{repo}<br/>Title + 单行成员头像 Hover 卡片 · Issue 正文动态；无 Board"]
    MEMBERS["成员展示页 /{owner}/{repo}/members<br/>完整成员资料"]
    REGISTER["成员登记页 /{owner}/{repo}/members/register<br/>简单表单 · Bot Commit/PR"]
    KANBAN["Kanban 专注页 /{owner}/{repo}/kanban<br/>完整看板 · URL 筛选排序"]
    ISSUE["Issue 详情 /{owner}/{repo}/issues/{number}<br/>社区讨论优先 · 独立 URL"]
    TOPIC["Topic Page /topic/{owner}/{repo}/<br/>公开主题横卡 · Flex 项目卡；#31 独立模块"]
    TABS["讨论 / 劳动历史 Tab"]
    SIDE["左：项目导航 / 右：任务属性<br/>默认均隐藏"]
    CHANNEL["Channel / 频道（#20 另行探索）"]
    AI["AI 摘要 / Agent（未来实验）"]
    ROOT --> HOME
    ROOT -.->|"独立 Topic 路由（#31）"| TOPIC
    HOME --> MEMBERS
    MEMBERS --> REGISTER
    HOME -.->|"后续阶段：进入独立看板"| KANBAN
    HOME -->|"点击卡片"| ISSUE
    KANBAN -->|"点击卡片"| ISSUE
    ISSUE --> TABS
    ISSUE --> SIDE
    HOME -.-> CHANNEL
    ISSUE -.-> AI
```

**路由约束已确认**：`/` 平台入口、`/{owner}/{repo}` 仓库首页、`/{owner}/{repo}/members` 成员展示页、`/{owner}/{repo}/members/register` 成员登记页、`/{owner}/{repo}/kanban?filter=…&sort=…` 独立看板页（后置实现）、`/{owner}/{repo}/issues/{number}` 详情。**另有 #31 独立公开 Topic Page**：`/topic/{owner}/{repo}/`，不核验 Installation；不等同 #3 的平台级已接入 Topic 信息流。第一版项目主页不展示看板，也不提供首页 Board 预览。独立看板实现后，其 URL 筛选/排序应可分享、可刷新；独立 Issue 的直接访问与 Back/Forward 需成立。具体 query 参数 schema 尚待定稿。

## 7. 维护规约

1. 每次完成一次实质性设计决策，**先更新[设计基线](./LabourChain-Repo-Board-Issue-UX-Baseline.md)**，再更新本图中对应节点；不要仅保存在聊天中。
2. 「✅」只代表**这项产品决策被确认**；不得据此把同一页面的 **D3/D4** 默认为完成。只有具备可复核的原型/走查记录时，才能将验证列升级。
3. 不以任意比例（如“设计完成 80%”）替代逐项状态。
4. 对后来改变的决定保留**旧规则 → 新规则 → 修改原因**的记录；避免老候选文字再次主导实现。
5. 需要实际代码检查才能得出的实现状态，应单独建立工程核验记录，不由本地图推断。
