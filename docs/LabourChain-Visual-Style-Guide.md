# LabourChain 视觉风格与配色规范（D2 初版）

> **产品方向已确认：2026-11-12。** 风格依据为《绝区零》绳网（Inter-Knot）的暗色信息界面、卡片与胶囊层次，加上 Discord 偏蓝蓝紫色的社区氛围。
>
> **状态边界：** 方向为用户确认的 **D1**；以下颜色值与组件使用方式为 Designer 的 **D2 规范初版**，尚未经过真实浏览器色彩、对比度、窄屏与用户 D4 验收。没有修改业务组件或部署。

## 1. 风格定位与取舍

| 视觉维度 | LabourChain 规范 | 避免的表现 |
| --- | --- | --- |
| 基础界面 | 深炭黑底 + 深灰蓝分层表面，连续阅读区清楚 | 大面积纯黑、过强装饰图案 |
| 信息组织 | 绳网式模块化文章卡片、紧凑信息行、清晰分隔 | 将项目首页做成游戏操作 HUD 或任务奖励面板 |
| 主要强调 | Discord 蓝紫色系，**偏蓝**；主操作、链接、选中/聚焦 | 多处蓝黄同时争夺视觉主次 |
| 次级强调 | 少量亮黄用于可信的特殊强调/选中提示，适量青色用于信息辅助 | 无数据依据的「高危」「热门」「完成进度」等装饰性状态 |
| 文字排版 | 标题紧凑醒目，长篇 Issue/README 保持高可读性 | 游戏专有字体、描边发光正文、大段全大写 |
| 动效装饰 | 短时、轻量反馈，纹理仅作低对比背景 | 闪烁、滚动视差、重度霓虹和自动播放 |
| 品牌资产 | LabourChain 原创图形与图标 | 直接挪用游戏截图、Logo、角色形象、Discord Logo 或产品专有界面素材 |

**参考来源（只作风格观察，不作为素材许可）：**
- [《绝区零》绳网动态界面参考图（電撃オンライン）](https://dengekionline.com/article/images/202407/9686/72894)：暗色底、独立卡片、醒目的导航选中。
- [《绝区零》Inter-Knot 等级界面（Push Square）](https://www.pushsquare.com/guides/zenless-zone-zero-how-to-increase-inter-knot-level)：深浅灰层级、胶囊信息列表、局部高亮。
- [Discord 官方品牌色](https://discord.com/branding)：Blurple `#5865F2` 与 Light Blurple `#E0E3FF`。LabourChain 使用独立偏蓝变体，不采用 Discord Logo 或品牌资产。

## 2. 色彩 Token（D2 建议值）

以下是**视觉目标色**，用于统一页面设计评审。可按对比度及真实显示反馈微调，不要求 Coder 按特定文件/组件结构实现。颜色命名只表达设计语义。

| 语义 Token | 推荐色值 | 视觉用途 |
| --- | --- | --- |
| `canvas` | `#11141B` | 全站默认暗色画布 |
| `surface` | `#191E29` | 主卡片、详情内容区 |
| `surface-raised` | `#242B3B` | Popover、表单强调区、选中背景 |
| `surface-input` | `#202737` | 输入框、代码块次级背景 |
| `stroke` | `#3C4659` | 卡片边线、分割线、无障碍分区 |
| `text-primary` | `#F5F7FF` | 标题、正文和主要数据 |
| `text-secondary` | `#C3CCDC` | 描述、时间、字段说明 |
| `text-muted` | `#96A4C0` | 次级元信息；仍需保持可读 |
| `primary-solid` | `#5368E9` | 主按钮、选中胶囊的背景 |
| `primary-hover` | `#465BD2` | 主按钮 Hover/按下 |
| `primary-link` | `#92A6FF` | 暗底上的正文链接、可操作文字 |
| `primary-focus` | `#ACB7F8` | 键盘焦点外轮廓 |
| `signal-yellow` | `#FBE13B` | 少量绳网风格强调，深色字 |
| `signal-cyan` | `#49D5E6` | 少量信息提示、辅助标记（非必需） |
| `state-success` | `#72DDB0` | 成功反馈，需配文案 |
| `state-warning` | `#F4C15D` | 警告反馈，需配文案 |
| `state-error` | `#FF8498` | 错误反馈，需配文案 |

**颜色关系：**
- `primary-solid` 是以 Discord Blurple 的蓝紫色相为参考、向蓝色略作偏移的 LabourChain 独立主色；`#5865F2` 不是复制整站样式的授权或必须一比一使用的常量。
- 主按钮采用蓝紫底＋白字；亮黄底使用深色文字。暗底普通链接使用比蓝色按钮更亮的 `primary-link`，避免深蓝链接在暗底上难读。
- `signal-yellow` 是辅助强调，不自动等于「warning」；真实警告使用语义化 `state-warning`，真实失败使用 `state-error`。
- 背景允许极弱的抽象网格、点阵或斜纹，但不得影响正文阅读，不复刻绳网原画或品牌图形。

### 2.1 色彩对比度（配对初检，非设备实测）

按照标准 sRGB 相对亮度公式进行**设计阶段数值初检**：

| 前景 / 背景 | 对比度（约） | 使用指导 |
| --- | --- | --- |
| `#F5F7FF` / `#11141B` | 17:1 以上 | 适用长篇正文 |
| `#C3CCDC` / `#191E29` | 10:1 左右 | 适用说明文字 |
| `#92A6FF` / `#11141B` | 8:1 左右 | 适用暗底链接 |
| 白字 / `#5368E9` | 约 4.6:1 | 主按钮文案可用，实际状态需复核 |
| `#11141B` / `#FBE13B` | 约 13:1 | 亮黄强调标签内文字 |

文字目标：常规正文、输入内容、按钮标签和状态提示至少达到 WCAG AA 的 4.5:1；较大的标题至少 3:1；焦点、边界和控件状态应能清楚辨认。**色彩值是建议设计 Token，非已经通过实际无障碍测试的声明。**

## 3. 页面与控件的视觉层级

### 3.1 项目主页 `/{owner}/{repo}`

- 顶部保留 `owner/repo` 次级身份、项目标题、Description/README 文本入口的既有层级；标题白色，次级信息灰蓝，链接亮蓝紫。
- Hero 以深色画布形成宽松阅读区；可用极轻的方向线/网格分隔区域。不要插入大幅游戏海报或遮挡项目简介的背景。
- Team 保留**单行头像**；焦点用蓝紫亮环，Hover 资料卡使用 `surface-raised`＋明确边线，卡片可进入、可阅读。
- Repo Feed 为核心阅读区：深色文章卡片，标题比正文 Markdown H1 更醒目；作者/时间信息可采用细小胶囊或紧凑信息行。Open/Closed 保留真实文字，不用仅靠颜色区分。
- Issue 的图片、视频外链块、代码块应适配暗色表面；不因此新增视频播放能力。

### 3.2 成员页与登记页

- 成员资料卡延续 `surface`；姓名白色、角色灰蓝，个人链接亮蓝紫；保留头像失效回退。
- 登记表单区域使用一致的暗色输入底、描边与标签间距；主要提交操作使用 `primary-solid`，取消/返回保持低强调度。
- 表单验证错误在字段附近显示错误文本与边框，并保持明显焦点；错误状态不单独依赖红色表达。权限/等待 PR/成功反馈继续由实际服务端状态决定。

### 3.3 Issue 详情与后续 Kanban

- 详情页的标题、来源、讨论/劳动 Tab、摘要和编辑区采用相同背景/文字/按钮/焦点体系；选中 Tab 使用蓝紫，黄色只用于有依据的特别提示。
- 后置 Kanban 继承相同色彩语义，不重新设计 Board 行为或 Label 数据契约。拖动与权限反馈仍按既有产品规则执行。

### 3.4 输入与状态

- 正常、Hover、Focus、Selected、Disabled、Loading、Error、Success 均需有**颜色以外**的状态线索（文字、边框、形状或位置）。
- 焦点环在主背景与卡片背景均清楚；键盘聚焦不可由 Hover 替代。交互目标仍按已有窄屏与可访问性约束设计。
- 动效不承担解释数据的唯一作用；尊重减少动态效果偏好。
- 本轮不新增可切换亮色主题，后续需要时另行制定完整 Token 及行为规则。

## 4. 当前源码的视觉审查快照（2026-11-12，`main` 静态核对）

| 已核对区域 | 现有视觉依据 | 与新方向的差距 |
| --- | --- | --- |
| `apps/playground/src/style.css` | 画布 `#f5f7fa`、白底列表、传统蓝链接 `#195ca8`；部分入口继续使用全局 `.shell` 样式 | 仍是浅色原型，与暗色主题不符 |
| `plugins/repo-home/src/RepoHome.module.css` | 白色 Card/MemberCard/Popover，`#202c3c` 深色字，传统蓝链接 | Hero、Team、Feed、登记尚未应用暗色层级与新 Token |
| `plugins/repo-home/src/SafeMarkdown.module.css` | 代码背景 `#f2f5f8`、深蓝链接、预览样式为浅色阅读区 | 长文、代码块、媒体外链须与暗色卡片协调 |
| `plugins/issue-detail/src/IssueDetailView.module.css` | 白色表单与错误卡片、`#edf3fa` 浅蓝摘要、深蓝主按钮 | 与新主页的文字、Tab、按钮、背景和焦点需要统一 |

**静态结论：** 当前代码中存在多套浅色规则，没有形成统一的暗色主题。现有响应式布局与行为规则继续保留；本文件只建立新视觉标准，不声称已经把源码改为新风格。

## 5. 绳网布局研究与方案

页面结构的具体提取见 [绳网布局提取与页面方案](./LabourChain-InterKnot-Layout-Study.md)，其中区分了**游戏截图可见层级**、**同人源码实现细节**和 **LabourChain D2 布局候选值**。

- **采用**：顶部暗色导航分区、清晰活动胶囊、卡片内部作者/标题/正文分区、局部非对称卡片轮廓、宽屏与窄屏的结构重排。
- **当前首页仍保持**：Hero → 单行 Team 头像 → 单列文章式 Repo Feed；保留 Issue 第一楼 Markdown 长文、媒体块和详情独立路由。
- **暂不采用**：游戏/同人三列封面瀑布流替代 Repo Feed、对话式 Issue 详情弹层、等级进度、无来源的封面和热度数字。
- **候选布局参数**：页面上限约 1120px、正文阅读区约 760px、手机边距 16px、正文卡片间距 16px。它们是后续屏幕比较的设计提案，尚非官方游戏规范或产品方最终确认的像素规格。

## 6. 设计验证与交付边界

- **已确认（D1）：** 暗色绳网式信息界面 + Discord 偏蓝蓝紫主交互色是产品的正式视觉方向。
- **已给出（D2 初版）：** 推荐 Token、页面色彩层级、可访问性目标和源码差距；具体视觉需与真实页面对照后再锁定。
- **未完成：** 全站 UI Tokens 落地、真实截图对照、窄屏与 200% 缩放及 D4 用户可用性验证。
- **Designer 可交付：** 设计规范、源码视觉差距、静态设计复审；有条件时做本地辅助复审。
- **Coder/Lead 负责：** 自行规划 CSS/组件实施、工期与代码审查，用户授权后推进；Designer 不代写工程架构方案。
- **用户负责：** 真实线上浏览器视觉和 #51 D4 验收。Designer 不请求 Vercel 团队访问权，也不执行真实 GitHub 写入。
