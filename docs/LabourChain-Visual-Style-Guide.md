# LabourChain 视觉风格与配色规范（Dark / Light 双主题 · D2）

> **用户确认：** 2026-11-12 确定绳网式卡片和 Dark 的 Discord 偏蓝蓝紫色；2026-11-13 确认五页暗色稿属于 **Dark Mode**，同时提供 **Light Mode**；最新决定：**Light 改用冷柠檬黄绿（Lime）为唯一品牌主色，移除 Light 的蓝紫色**。两种模式保留同一套页面结构与 LabourChain 身份识别。
>
> **阶段：** 双主题存在性及五页 D2 主布局已由用户决定；下列 Light 色值、按钮状态及切换入口是 **Designer D2 建议**，尚未逐项视觉确认。代码实现、真实浏览器、200% 缩放及用户 D4 均未验收。

## 1. 风格定位与取舍

| 视觉维度 | LabourChain 规范 | 避免的表现 |
| --- | --- | --- |
| 基础界面 | Dark：深炭黑 + 深灰蓝；Light：冷灰绿白纸面 + 雾白卡片 + 淡 Lime 次级分区 | Light 的暖金/蓝紫双重品牌强调、荧光 Lime 铺底、纯白刺眼对照 |
| 信息组织 | 绳网式模块化文章卡片、紧凑信息行、清晰分隔 | 将项目首页做成游戏操作 HUD 或任务奖励面板 |
| 主要强调 | **Dark** 沿用偏蓝的蓝紫主交互；**Light** 使用单一冷柠檬黄绿（Lime）色相，主按钮/选中为明亮 Lime + 深色字，链接/焦点使用同一色相的较深绿色 | Light 混入蓝紫或独立装饰黄；高亮按钮使用白字造成低对比 |
| 次级强调 | Dark 保留少量既有亮黄/青色；Light 使用淡 Lime 标签与深绿字，禁用独立金黄或蓝紫装饰 | 无数据依据的「高危」「热门」「完成进度」等装饰性状态 |
| 文字排版 | 两套模式共用标题层级、字重、间距与阅读行宽；分别提供深/浅可读文字色 | 游戏专有字体、描边发光正文、大段全大写 |
| 动效装饰 | 短时、轻量反馈，纹理仅作低对比背景 | 闪烁、滚动视差、重度霓虹和自动播放 |
| 品牌资产 | LabourChain 原创图形与图标 | 直接挪用游戏截图、Logo、角色形象、Discord Logo 或产品专有界面素材 |

**参考来源（只作风格观察，不作为素材许可）：**
- [《绝区零》绳网动态界面参考图（電撃オンライン）](https://dengekionline.com/article/images/202407/9686/72894)：暗色底、独立卡片、醒目的导航选中。
- [《绝区零》Inter-Knot 等级界面（Push Square）](https://www.pushsquare.com/guides/zenless-zone-zero-how-to-increase-inter-knot-level)：深浅灰层级、胶囊信息列表、局部高亮。
- [Discord 官方品牌色](https://discord.com/branding)：Blurple `#5865F2` 为 **Dark Mode 的历史色相参考**；Light Mode 的现行决定是 **Lime**，不再以 Discord 蓝紫配色为 Light 的配色依据。不采用 Discord Logo 或品牌资产。

## 2. 双主题色彩 Token（D2 建议值）

**Dark Mode 保留已确认的蓝紫 + 少量明黄色彩**，不进行修改。**Light Mode 改用冷 Lime（柠檬黄绿）一套色阶**：冷灰绿白画布、近白卡片、淡黄绿表面、明亮 Lime 按钮/选中态与深橄榄绿链接/焦点。取消 Light 原有的蓝紫主色、蓝灰标签及独立金黄色装饰。

**Lime 适用于品牌及普通交互，语义警告/错误仍保留各自有文字和图标的语义色。** 明亮 Lime 按钮必须搭配深色文字；正文链接采用更深的同色相，不以亮 Lime 充当小字颜色。以下数值为 Designer D2 候选，用户确认的是色相及去蓝紫方向，具体色值仍待真实页面视觉核对。

| --- | --- | --- | --- |
| `canvas` | `#11141B` | `#F5F7F1` | 页面冷灰绿白画布 |

| `stroke` | `#3C4659` | `#D4DFC9` | 低强调装饰分隔线 |
| `stroke-strong` | `#71809B` | `#7D9468` | 输入框和重要控件边线 |
| `text-primary` | `#F5F7FF` | `#283327` | 深绿灰正文/标题 |

| `state-error` | `#FF8498` | `#AC334B` | 实际错误反馈专用 |

**使用约束：**

- Dark 的既定 `primary-solid`、文字、亮黄不变；Light 的**品牌 Logo 衬底、主按钮、活动标签、卡片强调条、交互链接、焦点环**全部使用 Lime 色阶，**不出现蓝紫或单独金黄色品牌装饰**。
- Light 主按钮/活动胶囊：`#D3E985` 底 + `#283327` 字。禁止直接沿用 Dark 的白字按钮规则；亮绿浅底 + 白字对比度不足。
- Light 标准文字保持深灰绿；轻背景上的正文链接用 `#4A661B`，不将按钮亮 Lime `#D3E985` 用于小字号链接。
- Light 页头、Hero、Topic 顶部主题卡、Repo Feed、成员卡与表单按同一套冷绿中性色分层。通过字重、边界和间距建立层级，不制造高饱和“荧光绿整屏”。
- Loading、Selected、Open/Closed、Success、Warning、Error 都需要文字/图标/边界说明。真实语义 Warning 仍可使用琥珀色且仅在确有警告时出现；Error 保留红色，不能为了“单主色”抹掉状态含义。
- 真实图片、头像、Topic 主办方海报与封面保留原色；禁用全图反转与统一 Lime 滤镜。

### 2.1 色彩对比度数值初检（sRGB 计算，非浏览器实测）

| 前景 / 背景 | 对比度约值 | 作用 |
| --- | --- | --- |
| Dark `#F5F7FF` / `#11141B` | 17.5:1 | 标题/正文；原 Dark 保留 |
| Dark `#92A6FF` / `#11141B` | 8.0:1 | Dark 正文链接 |
| Dark 白字 / `#5368E9` | 4.6:1 | Dark 主按钮 |
| Light `#283327` / `#F5F7F1` | 12.2:1 | 页面标题与正文 |
| Light `#4B5B46` / `#FCFDF9` | 7.1:1 | 说明文字 |
| Light `#5B6B55` / `#FCFDF9` | 5.6:1 | 元信息 |
| Light `#283327` / `#D3E985` | 9.9:1 | **Lime 主按钮深色字** |
| Light `#283327` / `#C4DE6C` | 8.8:1 | Hover/Press 深色字 |
| Light `#4A661B` / `#FCFDF9` | 6.4:1 | 正文链接 |
| Light `#6C8A2A` / `#F5F7F1` | 3.7:1 | Focus 可见环 |
| Light `#7D9468` / `#F6F9F0` | 3.1:1 | 输入边线 |
| Light `#465F18` / `#E7F0C7` | 6.1:1 | 淡 Lime 标签文字 |

目标：正文/按钮文字至少 4.5:1；非文字的关键控件边界/焦点以 3:1 为目标；浅色纯装饰分割线可低对比，不能承担唯一的输入框边界。以上仅基于色值数值计算，实际网页状态、设备、缩放和 D4 由用户验证。

### 2.2 主题切换交互（D2 建议；产品机制尚待单独确认）

- **推荐控件**：站点级外观选项「跟随系统 / 浅色 / 深色」，放在实际存在的全站账户/设置导航中，若尚无稳定入口则先保留规范，不虚构按钮；不得替换业务操作控件。
- **推荐优先级**：用户显式选择优先；未选择时参考 `prefers-color-scheme`。页面跳转、刷新及五页间切换后保持一致。持久化存储位置和首次访问默认由工程/产品另定，不能假称已实现。
- **即时效果**：仅颜色、边框、背景纹理与状态色变化；Route、GitHub 数据、Issue 内容、Team 顺序、表单草稿、Tab、权限结果和滚动交互不改变。切换本身不能触发 GitHub API 写操作。
- **可访问性**：切换入口可聚焦、可操作，明确当前状态；尊重减少动态效果偏好，不使用闪烁或整屏明暗闪变作为反馈。
- **异常**：系统主题变化、页面初次呈现和本地偏好失效等情形应有稳定一致的可见表现，但具体存储/初始化技术由工程决定。

## 3. 页面与控件的视觉层级

### 3.1 项目主页 `/{owner}/{repo}`

- 顶部保留 `owner/repo` 次级身份、项目标题、Description/README 文本入口的既有层级；文字使用主题 `text-primary/secondary`，链接使用主题 `primary-link`。
- Hero 在 Dark 用深蓝灰层级，Light 使用冷灰绿白/淡 Lime 次级面；字号、正文位置和分区关系不变。Light 不使用蓝紫或独立金黄装饰。
- Team 保留**单行头像**；焦点环与 Hover 资料卡按当前主题 Token 配色，资料卡在两种模式都可进入、可阅读，头像和个人内容不反色。
- Repo Feed 为核心阅读区：Dark/Light 分别使用深色/白色文章卡，Issue 标题比正文 Markdown H1 更醒目；作者/时间用细小胶囊或紧凑信息行。Open/Closed 保留真实文字，不用颜色代替状态。
- Issue 图片、视频外链与代码块分别适配两种 `surface-input` 和边界；原图不作滤镜反转，不新增视频播放功能。

### 3.2 成员页与登记页

- 成员资料卡延续主题 `surface`；姓名使用 `text-primary`、角色使用 `text-secondary`、个人链接使用 `primary-link`；保留头像失效回退。
- 登记表单区域按主题使用一致的 `surface-input`、`stroke-strong` 和标签间距；主要提交操作使用 `primary-solid`，取消/返回保持低强调度。
- 表单验证错误在字段附近显示错误文本与边框，并保持明显焦点；错误状态不单独依赖红色表达。权限/等待 PR/成功反馈继续由实际服务端状态决定。

### 3.3 Issue 详情与后续 Kanban

- 详情页标题、讨论/劳动 Tab、摘要和编辑区沿用主题语义色。Dark 允许少量既有装饰黄；Light 使用冷绿灰分区与 **Lime 活动 Tab + 深色文字**，普通状态条不使用蓝紫或独立金黄装饰。
- 后置 Kanban 继承相同色彩语义，不重新设计 Board 行为或 Label 数据契约。拖动与权限反馈仍按既有产品规则执行。

### 3.4 输入与状态

- 正常、Hover、Focus、Selected、Disabled、Loading、Error、Success 均需有**颜色以外**的状态线索（文字、边框、形状或位置）。
- 焦点环在主背景与卡片背景均清楚；键盘聚焦不可由 Hover 替代。交互目标仍按已有窄屏与可访问性约束设计。
- 动效不承担解释数据的唯一作用；尊重减少动态效果偏好。
- **用户已明确要求支持 Dark 与 Light**；主题切换控件、默认值与偏好记忆细节依第 2.2 节作为 D2 建议，待产品进一步确认；不可将「Light 已设计」误记为「切换已实现」。

## 4. 当前源码的视觉审查快照（2026-11-12，`main` 静态核对）

| 已核对区域 | 现有视觉依据 | 与新方向的差距 |
| --- | --- | --- |
| `apps/playground/src/style.css` | 画布 `#f5f7fa`、白底列表、传统蓝链接 `#195ca8`；部分入口继续使用全局 `.shell` 样式 | 仍是浅色原型，与暗色主题不符 |
| `plugins/repo-home/src/RepoHome.module.css` | 白色 Card/MemberCard/Popover，`#202c3c` 深色字，传统蓝链接 | Hero、Team、Feed、登记尚未应用暗色层级与新 Token |
| `plugins/repo-home/src/SafeMarkdown.module.css` | 代码背景 `#f2f5f8`、深蓝链接、预览样式为浅色阅读区 | 长文、代码块、媒体外链须与暗色卡片协调 |
| `plugins/issue-detail/src/IssueDetailView.module.css` | 白色表单与错误卡片、`#edf3fa` 浅蓝摘要、深蓝主按钮 | 与新主页的文字、Tab、按钮、背景和焦点需要统一 |

**静态结论（2026-11-12 快照）：** 当前代码有多套未经统一的浅色规则。这些规则**不自动等同新增的 Light Mode**；全站既未实现既定 Dark Mode，也未按本文件统一 Light Mode 的 Token/状态。现有响应式和业务语义继续保留；本轮只更新设计标准。

## 5. 绳网布局研究与方案

页面结构的来源研究见 [绳网布局提取与页面方案](./LabourChain-InterKnot-Layout-Study.md)，其中区分了游戏截图、同人源码与 LabourChain 推导。**用户已确认五页演示的主布局**，完整桌面/手机页面结构以 [五页面 D2 布局设计](./LabourChain-Five-Page-Layout-Design.md) 为准：Repo Home、成员列表、成员登记、独立 Issue、公开 Topic Page（#31）。具体像素/色彩仍为建议，D4 未测。

- **采用**：顶部暗色导航分区、清晰活动胶囊、卡片内部作者/标题/正文分区、局部非对称卡片轮廓、宽屏与窄屏的结构重排。
- **当前首页仍保持**：Hero → 单行 Team 头像 → 单列文章式 Repo Feed；保留 Issue 第一楼 Markdown 长文、媒体块和详情独立路由。
- **Topic Page 区别**：#31 的顶部主题卡应以真实主办方海报为视觉中心，下方为自适应封面项目卡；它是独立公开 Topic 聚合，不对项目作 Installation 接入判断。
- **暂不采用**：游戏/同人三列封面瀑布流替代 Repo Feed、对话式 Issue 详情弹层、等级进度、无来源的封面和热度数字。
- **候选布局参数**：页面上限约 1120px、正文阅读区约 760px、手机边距 16px、正文卡片间距 16px。它们是后续屏幕比较的设计提案，尚非官方游戏规范或产品方最终确认的像素规格。

## 6. 设计验证与交付边界

- **已确认（D1）：** Dark 保持原蓝紫 + 局部明黄的绳网式暗色界面；Light **改用冷柠檬黄绿（Lime）作为唯一品牌主色并移除蓝紫**。两种主题共用五页布局、路由和数据语义。
- **已给出（D2 Lime 修订）：** Light 提供冷灰绿白画布、雾白卡片、淡 Lime 次级层、明亮 Lime 主操作/深色字、深橄榄链接/焦点及语义状态；原蓝紫与独立金黄品牌色从 Light 移除。精确色值与切换机制仍待用户实屏确认。
- **未完成：** 两套主题的 UI Token 实现、主题切换、五页实屏对照、窄屏/200% 缩放与 D4 用户可用性验证。
- **Designer 可交付：** 设计规范、源码视觉差距、静态设计复审；有条件时做本地辅助复审。
- **Coder/Lead 负责：** 自行规划 CSS/组件实施、工期与代码审查，用户授权后推进；Designer 不代写工程架构方案。
- **用户负责：** 真实线上浏览器视觉和 #51 D4 验收。Designer 不请求 Vercel 团队访问权，也不执行真实 GitHub 写入。
